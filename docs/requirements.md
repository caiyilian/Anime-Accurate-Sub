# Anime Accurate Sub - 项目需求文档

## 项目概述

输入一个视频文件，自动嵌入精准的中文字幕。主要用于没有中文字幕的日语动漫视频。

## 核心痛点

- 日语动漫缺乏中文字幕，手动找字幕很麻烦
- 浏览器自动字幕翻译工具（如 YouTube 自动翻译）错误率很高，翻译不准确
- 现有方案对动漫领域的专有名词、角色名、语气词等处理较差

## 核心需求

### 1. 语音识别 (ASR)
- 从视频中提取日语语音
- 对日语动漫语音有较高的识别准确率
- 支持说话人区分（角色分离）

### 2. 翻译 (Translation)
- **日语 → 中文** 的准确翻译
- 对动漫场景、口语化表达、角色语气有良好表现
- 保持角色名称翻译的一致性
- 支持专有名词（招式、地名、术语等）的准确翻译

### 3. 字幕嵌入 (Subtitle Embedding)
- 将翻译后的中文字幕嵌入视频文件
- 支持 ASS/SRT 等常见字幕格式
- 字幕样式美观（字体、大小、位置、描边等）
- 支持双语字幕（日语原文 + 中文翻译）可选

### 4. 本地运行 (Local Execution)
- **必须支持通过 Ollama 运行本地模型**，不需要依赖云端 API
- 也可选支持调用云端 API（如 OpenAI、Claude 等）作为备选
- 敏感数据不上传外部服务

## 技术栈方向（待定）

| 模块 | 候选方案 |
|------|---------|
| 语音识别 (ASR) | Whisper / Faster-Whisper / SenseVoice / 本地模型 |
| 说话人分离 (Diarization) | pyannote.audio / 其他方案 |
| 翻译 (Translation) | Ollama 本地 LLM（如 Llama、Qwen 等）/ 云端 API 备选 |
| 字幕封装 | FFmpeg / ass 库 |
| 语言 | Python（优先） |
| 其他工具 | yt-dlp（视频下载，可选） |

## 工作流程

```
输入视频文件
    ↓
提取音频轨道
    ↓
语音识别 (ASR) → 日语原文 + 时间戳
    ↓
（可选）说话人分离
    ↓
日语文本分段
    ↓
翻译为中文（Ollama 本地模型 / API）
    ↓
生成字幕文件 (SRT/ASS)
    ↓
────────────────────────────────────────
   【多 Agent 脚本审查】★
   导出为轻小说格式纯文本
    → 多个 Agent 并行审查
    → 汇总修正建议 → 自动修正字幕
    → 输出审查报告（仅极高风险项留待人工确认）
────────────────────────────────────────
    ↓
嵌入视频 → 输出带字幕的视频
```

### 多 Agent 脚本审查阶段

**目的**：在嵌入视频前，用多个 AI Agent 协作审查整集字幕的逻辑通顺性和翻译质量，**尽可能减少人工介入**。

**为什么需要**：
- 看视频时画面和声音会分散注意力，不易发现翻译层面的逻辑问题
- 读文本能快速发现角色名不一致、人称指代混乱、上下文逻辑断裂
- 多 Agent 从不同角度审查，比单一模型一次性输出质量更高

**Agent 角色设计**（全部基于同一个 Ollama 本地模型，但分工不同）：

| Agent | 职责 | 审查角度 |
|-------|------|---------|
| **📋 格式化 Agent** | 将 SRT/ASS 转为轻小说格式文本 | 提取纯对话流，按时间排序 |
| **🔍 一致性 Agent** | 检查角色名、术语、人称代词是否前后一致 | 扫描全文，标记不一致处 |
| **🧠 逻辑 Agent** | 阅读对话流，检查上下文逻辑是否通顺 | "A 说 X → B 回答 Y" 是否合理 |
| **🌊 翻译自然度 Agent** | 检查中文是否自然，是否有翻译腔 | 是否符合角色性格、口语化程度 |
| **🎯 ASR 纠错 Agent** | 结合日语原文，怀疑 ASR 误听导致语义不通 | 标记可疑的 ASR 输出 |
| **📝 总编 Agent** | 收集所有 Agent 的反馈，冲突裁决，生成最终修正方案 | 汇总、去重、优先级排序 |

**工作流程**：
1. 格式化 Agent 将字幕转为轻小说格式文本
2. 一致性 Agent、逻辑 Agent、翻译自然度 Agent、ASR 纠错 Agent **并行**审查
3. 总编 Agent 收集所有反馈，排除误报，合并冲突，生成修正列表
4. 自动应用修正到字幕文件（只改有问题的行，不重跑 ASR 和翻译）
5. 输出审查报告：修正了哪些、为什么修正、剩余高风险项（如有）

**目标**：95% 以上的问题由 Agent 自动发现并修正，仅极少数模棱两可的高风险项留待人工确认。

## 未来拓展方向

### 第一阶段（管道完善后添加）

- [ ] **说话人分离与角色标注（Speaker Diarization）** — 识别不同说话人，在字幕中标注当前是谁在说话，不同角色使用不同颜色标签
- [ ] **术语表系统（Glossary）** — 用户自定义角色名、招式名、地名等专有名词的翻译映射，确保跨剧集翻译一致性
- [ ] **翻译记忆库（Translation Memory）** — 缓存已翻译的句子，相同台词直接复用，避免重复翻译和不一致
- [ ] **OP/ED 自动检测与跳过** — 自动识别片头片尾，防止 ASR 在歌词上浪费资源，同时避免翻译歌词
- [ ] **多 Agent 脚本审查** — 5 个 Agent 并行审查（一致性/逻辑/翻译自然度/ASR纠错/总编），自动修正问题，95%+ 无需人工介入

### 第二阶段（体验完善）

- [ ] **双语字幕模式** — 日语原文 + 中文翻译同时显示，上日下中或左日右中布局
- [ ] **断点续传（Resume from Checkpoint）** — 长视频处理中断后从中断处继续，而非重新开始
- [ ] **批量处理（Batch Processing）** — 一次性提交多集动漫，自动排队处理
- [ ] **字幕时间轴优化** — 自动检测重叠字幕、调整过短/过长的显示时间，确保阅读舒适度
- [ ] **多种字幕样式模板** — 提供多套 ASS 预设样式（字体、大小、颜色、描边、位置等）

### 第三阶段（高级功能）

- [ ] **Web UI 界面** — 图形化操作界面，上传视频 → 配置参数 → 下载结果
- [ ] **人工校对模式（Proofreading）** — 交互式界面让用户校对和修正翻译结果，支持导出/导入校对稿
- [ ] **翻译质量评估（TQE）** — 自动评估翻译质量，标记低置信度段落供人工审查
- [ ] **支持更多语言对** — 如英语→中文、日语→英语等
- [ ] **插件系统** — 允许社区开发翻译后端、ASR 后端、字幕样式等插件
- [ ] **视频预览** — 实时预览字幕效果，所见即所得

## 非功能性需求

- 支持 GPU 加速（CUDA）
- 良好的断点续传能力（避免长视频处理中途失败全部重来）
- 清晰的日志输出，方便排查问题
- 模块化设计，各组件可独立替换（ASR / 翻译 / 字幕引擎解耦）
- 自动检测硬件配置，推荐最优参数（模型大小、量化级别等）
