# Anime Accurate Sub 架构评审与技术建议

## 任务 1：项目方案评审

### 1.1 技术选型
* **ASR (Anime Whisper)**: 作为主力非常合理，它对二次元术语的拟合度极高。但动漫场景最大的痛点不是口音，而是**背景音乐（BGM）和夸张的音效（SFX）**。在没有音频预处理的情况下，直接输入原始音频会导致 Whisper 产生严重的幻觉（Hallucination），即在纯 BGM 片段疯狂输出无意义或重复的字幕。
* **翻译 (SakuraLLM)**: Sakura 是目前的无可争议的最优解。关于 CC BY-NC-SA 4.0，只要你不将该工具打包作为商业 SaaS 售卖，或者将生成的字幕用于商业盈利用途，纯粹作为本地工具是完全合规的。针对拥有 24GB 显存的高配环境，建议直接将主力翻译模型锁定为 `Sakura-14B-Q6_K`（约占用 12-14GB VRAM），剩余显存完全足够支撑上下文缓存，这能极大降低翻译的“机翻感”。
* **说话人分离 (Diarization)**: 动漫场景是 Diarization 的“地狱模式”。声优（Seiyuu）的声线变化极大（比如同一个声优配萝莉音和御姐音），而且常常伴随多角色叠音和 BGM。`pyannote` 在这种场景下错误率极高。建议初期降低对此功能的期望，或者必须在分离前进行极其干净的**人声提取**。

### 1.2 架构设计
* **JSONL 持久化**: 这是一个非常稳健且工程化的选择。JSONL 的 Append-Only 特性完美契合视频处理这种流式、耗时的任务，比 SQLite 更轻量，比完整 JSON 更防崩溃，天然支持断点续传。
* **多 Agent 审查**: 不引入庞大的框架是明智的。但设置 5 个独立 Agent 存在巨大的**延迟陷阱和上下文碎片化问题**。5 次独立的 LLM 调用不仅会让处理时间增加数倍，还会因为各自关注点不同导致“总编 Agent”难以调和冲突。建议将一致性、逻辑、自然度合并为一次 Prompt工程，通过 Few-Shot 示例让模型一次性输出修正结果。

### 1.3 优先级调整
* 当前阶段 1 的 **多 Agent 审查** 过于前置，会大幅拖慢跑通主流程的速度，建议移至阶段 3。
* **OP/ED 检测** 的优先级应该提高到阶段 0 或 1。跳过这 3 分钟的歌曲不仅能省去大量的无效 ASR 算力，还能避免歌词翻译污染本地的翻译记忆库。

## 任务 2：补充功能建议与实现路径

### 2.1 被忽略的“杀手级”功能
* **人声/BGM 强制分离 (Audio Separation)**: 这是提升动漫 ASR 准确率的最核心前置步骤。在丢给 Anime Whisper 之前，先用模型将音频剥离为“纯净人声”和“BGM”，只对人声部分做 ASR。这能将识别错误率和幻觉率大幅降低。
* **滑动窗口上下文翻译 (Context-Aware Translation)**: 日语经常省略主语，单句独立翻译必然导致人称代词（如把“我”翻成“你”）崩坏。在翻译第 $N$ 句时，必须将 $N-3$ 到 $N-1$ 句的日文和中文作为 Context 塞入 Prompt 中。
* **中日双语/注音 (Furigana) 渲染**: 对于学习日语的用户，可以利用 `pysubs2` 生成带有 Ruby 标签的 ASS 字幕，实现汉字上方显示平假名注音的功能。

### 2.2 更好的实现路径
不需要从零手搓所有管道。可以重点参考并 Fork **VideoLingo**。这是一个目前非常成熟的视频本地化工具，旨在生成 Netflix 级别的字幕，已经集成了 WhisperX 的词级对齐、NLP 字幕分割以及断点续传机制。你可以剥离它内置的通用大模型翻译，将你的 Anime Whisper 和本地 Ollama SakuraLLM 接入它的骨架，能省去大量的工程时间。

## 任务 3：补充调研

以下是针对动漫及字幕场景的重点项目补充：

1. **BS-RoFormer (音频分离 SOTA)**
   * **链接**: `https://github.com/lucidrains/BS-RoFormer`
   * **优势**: 字节跳动 AI Lab 提出的音乐源分离架构，利用频域和时域的轴向注意力机制，在分离纯净度和保留人声细节上具有领先优势。
   * **关注理由**: 用于提取动漫音频中的纯净人声，彻底解决 ASR 被 BGM 干扰的问题。结合开源社区的 `UVR5` 命令行工具使用，可实现全自动静默预处理。
2. **VideoLingo (端到端字幕对齐与翻译)**
   * **链接**: `https://github.com/Huanshere/VideoLingo`
   * **优势**: 专注于高质量的单行字幕切割（避免长短句不一）和低幻觉的字幕识别。它支持通过 Streamlit 提供多语言的 Web UI 界面，并且拥有详细的进度日志。
   * **关注理由**: 它的三步“翻译-反思-适配”机制和时间轴优化逻辑远比基础的线性切分要成熟。
3. **WhisperX (时间轴极致优化)**
   * **链接**: `https://github.com/m-bain/whisperX`
   * **优势**: 使用强制对齐（Forced Alignment）技术，极大解决 Whisper 原生时间戳漂移的问题。
   * **关注理由**: 动漫里的快节奏对话极易出现字幕时间轴延迟，WhisperX 是目前解决此问题的标配。

## 任务 4：整体技术建议与避坑指南

### 4.1 推荐的技术栈 (The Architect's Choice)
如果由我来主导，我会构建如下 Pipeline：
1. **预处理**: FFmpeg 提取音频 $ightarrow$ **UVR5 CLI (BS-RoFormer)** 提取纯净人声。
2. **ASR**: **Anime Whisper** (识别文本) 配合 **WhisperX** (进行词级时间轴强制对齐)。
3. **翻译**: **Sakura-14B-Q6_K** (Ollama 运行)。采用“滑动窗口+术语表”的单次 Prompt 请求，摒弃多 Agent 并发。
4. **后处理**: `pysubs2` 生成 ASS 字幕 $ightarrow$ FFmpeg 压制。
5. **持久化**: Python 标准库读取/追加 JSONL 记录状态。

### 4.2 MVP 最短路径 (第一周目标)
**砍掉一切进阶功能**，专注核心转换流：
* **Step 1**: 写一个 Python 脚本，调用 FFmpeg 提取一集动漫的音频。
* **Step 2**: 本地加载 Anime Whisper，将音频转换为带时间戳的 JSON。
* **Step 3**: 编写一个简单的翻译类，逐行读取 JSON，将单句文本发给本地 Ollama 中的模型。
* **Step 4**: 将翻译返回的中文，连同原始时间戳，组装成标准的 `.srt` 文件。
* *目标*: 只要能不报错地跑完一集并生成 SRT 就算胜利。说话人分离、记忆库、双语显示全部留到后续迭代。

### 4.3 高频“翻车点”提醒 (Pitfalls)
* **显存碎片化 (VRAM OOM)**：在同一套 Python 脚本中顺序加载 ASR 模型和 LLM 时，ASR 卸载不干净会导致随后的语言模型爆显存。建议 ASR 阶段和翻译阶段拆分为两个独立的进程（Process），通过 JSONL 文件通信，确保物理显存完全释放。
* **太碎的字幕切割**：Whisper 经常会输出半秒钟的短词（如“あの...”），如果直接翻译并生成字幕，屏幕上的字会闪烁得让人眼晕。必须在 ASR 和翻译之间加入合并逻辑，将时间间隔小于 0.5 秒且语意未尽的短句进行合并。
