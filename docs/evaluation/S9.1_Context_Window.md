# S9.1 上下文窗口翻译评估

> 日期：2026-07-13（2026-07-19 接入正式流水线）
> 目标：实现并验证上下文窗口翻译的效果，对比有无上下文的翻译质量差异

---

## 实现方案

### translate.py 翻译模块

新增 `scripts/translate.py`，支持：

| 功能 | 说明 |
|:----|:------|
| 单句翻译 | `python scripts/translate.py --text "日本語"` |
| 上下文翻译 | `--context-before / --context-after` 传入前后文 |
| 批量翻译 | `--batch examples.json --context-window 3` |
| 对比评估 | `--evaluate` 自动对比有无上下文 |

### 上下文拼接策略

```
对话历史：
- 前3句（如果存在）
当前句子：{需要翻译的句子}
后续句子（仅供参考）：
- 后3句（如果存在）
```

Prompt 要求模型只输出翻译结果，不重复上下文。

### 正式流水线接入

`scripts/anime_sub.py`、`PipelineTranslator` 和 Sakura/GalTransl/Qwen 适配器现已使用同一套上下文窗口。正式流水线按时间顺序逐句翻译，默认把已经通过校验的前 3 条中文译文放入 system 历史区；user 消息只包含当前日文句，不向 Sakura 暴露未来日文。完整的前后各 5 条上下文仍由后续五代理审查与 MQM 使用。

真实全流程探针证明，即使把未来日文放在 system 区，Sakura 仍会在连续相似台词中翻译并合并未来句，甚至偶发输出 system 指令。改用已确认的中文历史后，4 个失败样本全部恢复为干净单句。校验器同时拒绝“只输出 user 消息”等指令片段，以及原文没有三次重复但译文出现三次相同长短语的上下文合并。

可用 `--translation-context-window N` 调整中文历史长度，设为 `0` 时恢复带稳定行号的批量翻译，可用于无上下文对照。上下文模式下 `--translation-batch-size` 只控制进度与 TM 落盘频率；旧版第三方翻译插件若尚未声明上下文参数，流水线会保持兼容并按原接口调用。

### 环境变量支持

| 变量 | 说明 | 默认值 |
|:----|:------|:--------|
| `OLLAMA_HOST` | Ollama 服务器地址 | localhost |
| `TRANSLATION_MODEL` | 翻译模型名 | Sakura-7B |

## 评估结果

### 测试数据

10 句连续动漫对话（早安→问候→吉他练习→邀请合奏），模拟真实对话场景。

### 对比结果

| # | 日语原文 | 有上下文 | 无上下文 | 参考翻译 |
|:-:|:---------|:---------|:---------|:---------|
| 1 | おはよう、唯 | 早上好，唯 | 早上好，唯。 | 早安，唯 |
| 2 | あ、おはようございます！ | 啊，早上好！ | — | 啊，早上好！ |
| 3 | 今日も元気だね | 今天你也很精神啊 | — | 今天也很有精神呢 |
| 4 | はい！昨日新しいギターの練習したんです | 是的！昨天练习了新的吉他。 | 是的！昨天我练习了新的吉他。 | 是的！昨天练习了新吉他 |
| 5 | そうなんだ。上手くなった？ | 是吗。进步很大吧？ | — | 这样啊。有进步吗？ |
| 6 | まだまだですけど、楽しいです！ | 虽然还有进步的空间，但我很开心！ | — | 还差得远，但是很开心！ |
| 7 | 澪ちゃん、一緒に練習しない？ | "澪，一起练习吗？" | "澪酱，要不要一起练习？" | 小澪，要不要一起练习？ |
| 8 | いいよ。でも私、まだベース下手だから | 好啊。不过我还在练习，所以... | — | 好啊。不过我的贝斯还弹得很差 |
| 9 | そんなことないよ！澪ちゃんは上手だよ | 没关系，澪也很棒呢！ | — | 没那回事！小澪弹得很好 |
| 10 | ありがとう、唯。じゃあ放課後ね | 谢谢你，唯。那我们下午见吧。 | 好的，没问题。\n"谢谢你，唯。那么，我们下次见。" | 谢谢，唯。那放学后见 |

### 分析

| 维度 | 有上下文 | 无上下文 |
|:----|:---------|:---------|
| **角色名一致性** | ✅ "澪" / "唯" 保持一致 | ⚠️ "澪ちゃん"→"澪酱"不稳定 |
| **对话流畅度** | ✅ 语气自然承接上文 | ⚠️ 有时输出多行或格式混乱 |
| **翻译准确度** | ✅ 基本准确 | ✅ 基本准确 |
| **输出格式** | ✅ 单行干净输出 | ❌ 第10句输出了3行乱码 |

### 关键发现

1. **上下文窗口有效**：角色名一致性明显提升（"澪ちゃん" 统一翻译为 "澪"）
2. **对话流畅度提升**：有上下文时语气更自然（"今天你也很精神啊"承接"早上好"）
3. **无上下文偶发格式问题**：第10句无上下文时输出了3行混乱内容
4. **当前模型为 translategemma:4b**：Sakura-7B 模型暂时不可用，但上下文窗口逻辑与模型无关
5. **Sakura 模型恢复后效果预期更好**：Sakura 翻译质量本就优于 translategemma，加上上下文后效果会更好

## 结论

### 上下文窗口翻译有效，建议启用

| 场景 | 建议 |
|:----|:------|
| 连续对白翻译 | ✅ 开启上下文窗口（前3句） |
| 单句独立翻译 | 不需要上下文 |
| 首次运行/无历史 | 默认无上下文，逐步积累上下文 |

### translate.py 使用方法

```bash
# 单句翻译
python scripts/translate.py --text "おはよう"

# 带上下文翻译
python scripts/translate.py \
  --text "今日も元気だね" \
  --context-before "おはよう、唯||あ、おはようございます！"

# 批量翻译（JSON 数组）
python scripts/translate.py --batch sentences.json --context-window 3
```
