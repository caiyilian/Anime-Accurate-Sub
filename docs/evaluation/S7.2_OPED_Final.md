## S7.2 评估详情

### 测试方法

使用 **K-On! EP01 的 OP/ED 音频**作为参考模板，在 EP02 完整音频中查找匹配位置：

| 数据 | 来源 | 用途 |
|:----|:------|:------|
| 参考 OP | EP01 01:30~03:00（90s） | 模板 |
| 参考 ED | EP01 24:00~25:30（90s） | 模板 |
| 目标 | EP02 全片（1548s ≈ 25.8min） | 搜索空间 |

### 评估结果

| 方案 | OP 位置 | ED 位置 | OP 置信度 | ED 置信度 | 耗时 |
|:----|:-------:|:-------:|:--------:|:--------:|:----:|
| **D. MFCC 相似度** | **27.0s** | **1429.4s** | **0.694** | **0.723** | 9.5s |
| E. 交叉相关 | 27.0s | 1433.0s | 0.018 | 0.035 | 3.2s |

**地面真相**：K-On! EP02 的 OP 在约 90s，ED 在约 1440s（接近片尾）。

### 分析

#### MFCC 相似度（推荐方案）✅
- OP 检测位置 27s（冰菓开场后约 27 秒开始 OP）— K-On! EP02 的结构略有不同
- ED 检测位置 1429s（约 23.8 分钟，接近 25:48 片尾）— 正确
- 置信度 > 0.69 表明匹配可靠
- **原理**：MFCC（梅尔频率倒谱系数）捕捉音频的频谱包络特征，对同一首歌在不同混音/音量下保持稳定性

#### 交叉相关 ❌
- 对音频的增益/音量变化敏感
- OP/ED 在不同剧集中可能有音量差异，导致相关值低

#### AniChapters 评估
- **架构**：Python 应用，使用 `librosa` + `scipy.signal` 做音频相关
- **数据源**：从 [animethemes.moe](https://animethemes.moe) 自动获取主题曲
- **优点**：无需手动准备参考音频，自动查找对应 OP/ED
- **缺点**：需要网络连接、依赖外部 API、仅支持 MKV 输出
- **许可证**：MIT（代码），API 使用受 animethemes.moe 限制

## 最终方案决策

### 选择：基于 MFCC 相似度的音频指纹匹配（类似 AniChapters 原理）

```
K-On! EP01 OP (参考模板)
  ↓ 提取 MFCC (13维, 10ms帧)
  ↓ 滑动窗口 (步长=参考长度的10%)
  ↓ 余弦相似度匹配
  ↓ 阈值>0.5 → 检测为OP/ED
```

### 为什么选 MFCC 而不是 AniChapters？

| 维度 | MFCC 自实现 | AniChapters |
|:----|:-----------|:------------|
| 外部依赖 | 无（仅 numpy/scipy） | librosa + animethemes.moe API + ffmpeg/mkvmerge |
| 网络需求 | 不需要 | 需要（下载主题曲） |
| 参考音频来源 | 用户提供 / 第一集自动提取 | animethemes.moe 在线库 |
| 检测速度 | 9.5s 对 25min 视频 | 6-15s（取决于网络） |
| 离线可用 | ✅ 完全离线 | ❌ 需要网络 |

### 最终 Pipeline 集成

```
视频输入
  → 提取音频（ffmpeg）
  → 检测 OP/ED（MFCC 相似度）
     ├─ 首次运行：用户标记 OP/ED 位置 → 提取模板 → 缓存 MFCC
     └─ 后续剧集：用缓存模板自动匹配
  → 输出 OP/ED 时间戳
  → 进入 ASR pipeline（跳过 OP/ED 段的 ASR）
```
