## 四、三步翻译机制详解

VideoLingo 最核心的特色是其**三步翻译**流程：

### 4.1 第一步：总结与术语提取

在翻译前先对整个视频内容做总结，提取关键术语：

```json
// output/gpt_log/summary.json 示例
{
  "characters": ["唯", "律", "米由"],
  "summary": "轻音部招新场景，唯和米由讨论社团参观"
}
```

### 4.2 第二步：直译（Faithfulness）

逐句精确翻译，保持原文结构和含义：

| 原文 | 直译 |
|------|------|
| クラブ見学行こうぜ! | 一起去参观社团吧！ |
| でも私文芸部に入るつもりだしえ? | 可是我要进文艺部的说，诶？ |

### 4.3 第三步：意译（Expressiveness）

在直译基础上进行口语化润色，使其更自然：

| 原文 | 直译 | 意译 |
|------|------|------|
| クラブ見学行こうぜ! | 一起去参观社团吧！ | **走，去参观社团吧！** |
| でも私文芸部に入るつもりだしえ? | 可是我要进文艺部的说，诶？ | **可是我想进文艺部的…诶？** |
| 入部希望の紙も書いたしミヨー…いるわー! | 入部申请单我也写了，米由…走吧！ | **申请单我也填了…米由，等不了啦！** |
| 何すんだよリツ! | 你在干嘛呀，律！ | **你搞什么啊，律！** |

## 六、优缺点

### 优点

| 方面 | 评价 |
|------|------|
| **翻译质量** | 三步翻译机制效果显著，直译+意译双输出，自然度远超传统 MT |
| **ASR 速度** | WhisperX + VAD + GPU，30s 仅需 2.8s，比 pyVideoTrans 快 5x |
| **词级对齐** | wav2vec2 强制对齐，时间轴精确到词级 |
| **句子分割** | spaCy NLP + 语义分割，断句合理 |
| **Netflix 单行字幕** | 自动生成单行字幕，阅读体验好 |
| **输出丰富** | 4 种 SRT 格式 + 嵌入字幕的视频 |
| **术语表** | 自动提取术语+人工可干预 |

### 缺点

| 方面 | 评价 |
|------|------|
| **无 OP/ED 检测** | 片头片尾也会被 ASR 识别 |
| **无说话人分离** | 所有字幕同一风格 |
| **HuggingFace 强依赖** | 大量模型需从 HF 下载，国内网络受限 |
| **依赖复杂** | 需要 WhisperX + wav2vec2 + spaCy + Demucs 等多个大型依赖 |
| **翻译较慢** | 三步翻译需要多次 LLM 调用，比单步翻译慢 |
| **无 CLI** | 主要依赖 Streamlit UI，批量模式需 Excel 配置 |

## 八、结论

| 结论 | 说明 |
|------|------|
| **作为底座可行性** | ❌ 不适合直接作为底座 |
| **推荐复用方式** | 独立复用**三步翻译流程**和**词级对齐**模块 |

VideoLingo 的三步翻译机制是目前评估的两个项目中质量最好的，但其强依赖 HuggingFace、无 CLI 支持、依赖复杂，不适合直接作为项目底座。建议将其**三步翻译**和**词级对齐**作为可复用模块，整合到以 pyVideoTrans 为基础的自研 pipeline 中。
