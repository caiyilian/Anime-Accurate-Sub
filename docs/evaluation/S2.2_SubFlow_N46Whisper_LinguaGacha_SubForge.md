## 1. SubFlow — ✅ 测试通过

### 基本信息

| 项 | 值 |
|------|------|
| 仓库 | [nanguaguag/SubFlow](https://github.com/nanguaguag/SubFlow) |
| Python | 3.10+（测试于 3.13） |
| ASR 引擎 | OpenAI Whisper（非 faster-whisper） |
| 翻译 | GPT-4o-mini 等 LLM |
| 模式 | Anime（对话）+ Song（卡拉OK） |

### 测试结果（30s K-On! 片段，tiny 模型）

| 指标 | 值 |
|------|------|
| 模型加载 | 0.8s |
| ASR 转写 | 8.9s（OpenAI Whisper tiny, 27 raw segments）|
| 后处理 | 智能切分（语义合并过碎片段） |
| Python 3.13 | ✅ 通过（需 zipfile cp437 补丁） |

### 关键特性

- **专注动漫场景**：语义合并短句 + 标点优化阅读体验
- **智能切分**：基于 `split_gap` 参数自动合并间隔过短的片段
- **双语字幕**：支持 SRT + ASS（仿宋体/黑体）
- **歌曲模式**：逐字歌词时间戳（LRC/Karaoke ASS）
- **LLM 翻译**：支持 GPT-4o-mini 翻译，上下文记忆

### 优点与局限

| 优点 | 局限 |
|------|------|
| 代码极简（1 主文件 + 3 模块） | 使用 OpenAI Whisper（比 faster-whisper 慢） |
| 动漫场景特化 | 需 API Key 才能翻译 |
| 歌曲/卡拉OK 模式独特 | 无说话人分离 |
| 安装简单（pip install 即可） | 翻译仅支持 OpenAI 兼容 API |

## 3. LinguaGacha — ⏸️ 代码分析

### 基本信息

| 项 | 值 |
|------|------|
| 仓库 | [neavo/LinguaGacha](https://github.com/neavo/LinguaGacha) |
| 语言 | TypeScript（Node.js + Electron） |
| 类型 | **文本翻译器**（非 ASR 工具）|
| Stars | ~2K |
| 运行环境 | Node.js v24.6.0 可用 |

### 安装尝试

- Node.js 已安装（v24.6.0）
- 项目为 Electron 桌面应用，需要 `npm install` + `npm run dev`
- 由于 Electron 安装需要从 GitHub 下载二进制文件（~100MB），受代理限制无法完成

### 评估结论

- **不是 ASR 工具**：它是一个 AI 文本翻译器，用于翻译已有的字幕/小说/游戏文本
- 支持 SRT/ASS 字幕文件翻译 + Glossary 术语表自动生成
- 术语表功能是其独特价值：一键生成角色名/专有名词的译名统一表
- 如果作为翻译后端接入，可作为 VideoLingo 3-step 翻译的替代方案

## 4. SubForge — ✅ 构建成功

### 基本信息

| 项 | 值 |
|------|------|
| 仓库 | [deusjin/subforge](https://github.com/deusjin/subforge) |
| 语言 | Rust（v0.2.0, edition 2024）|
| 构建状态 | ✅ `cargo build --release` 成功（1min 8s）|
| ASR 引擎 | faster-whisper（通过 Python sidecar）|
| 翻译 | Google / Bing / OpenAI LLM |
| CLI 命令 | transcribe, subtitle, synthesize, translate, process, batch, eval, setup, doctor, model, gpu |
| 特色 | SaT 分割 + GEMBA-MQM 质量评估 |

### 构建与测试

```bash
git clone https://github.com/deusjin/subforge.git
cd subforge
cargo build --release  # 68s, Rust 1.89.0
```

- Rust 工具链已安装（rustc 1.89.0, cargo 1.89.0）
- 编译生成 `target/release/subforge.exe`
- CLI 支持中文输出：transcribe / subtitle / synthesize / process 等 14 个命令
- `subforge setup` 自动创建 Python venv 并安装 faster-whisper + wtpsplit 等依赖
- 需要 Python + faster-whisper sidecar（subforge 自动管理）

### 关键特性

- **SaT 分割**：通过翻译（Translation）来辅助语义断句，比纯规则分割更准确
- **GEMBA-MQM 质量评估**：用 LLM 评估翻译质量，自动标记低分片段重新翻译
- **faster-whisper 原生支持**：集成 faster-whisper Python sidecar
- **MAPS 术语提取**：项目级术语表 + 翻译记忆

### 优点与局限

| 优点 | 局限 |
|------|------|
| 编译后单二进制，部署简单 | 需要 Rust 工具链（初次构建） |
| 完整的 CLI 管线 | Python sidecar 增加了复杂度 |
| SaT 分割 + 质量评估 | 非动漫特化，通用工具 |
| 支持 NVENC 硬件编码 | 中文文档不完善 |

## 5. 四个项目对比

| 维度 | SubFlow | N46Whisper | LinguaGacha | SubForge |
|------|:-------:|:----------:|:-----------:|:--------:|
| 语言 | Python | Colab | TypeScript | Rust |
| ASR 引擎 | Whisper | faster-whisper | ❌ 无 | faster-whisper |
| 可本地测试 | ✅ | ❌ Colab | ❌ 非ASR | ⚠️ 需编译 |
| 动漫特化 | ✅ | ✅ | ❌ 通用 | ❌ 通用 |
| 独特价值 | 歌曲模式 | — | 术语表 | SaT 分割 + 质量评估 |

## 6. 结论

- **SubFlow** 值得关注的点在**歌曲逐字歌词模式**（LRC/Karaoke）和**智能切分**逻辑
- **LinguaGacha 的术语表（Glossary）功能**可以作为翻译后端的补充
- **SubForge 的 SaT 分割**值得作为研究方向
- 但 S2.2 的四个项目都没有比之前评估的项目（pyVideoTrans / VideoLingo / WhisperJAV / JAVTrans / AnimeTranslator）提供突破性的底座候选

**建议**：进入 S2.3 底座选型决策，基于 Sprint 1+2 所有评估结果做最终决定。
