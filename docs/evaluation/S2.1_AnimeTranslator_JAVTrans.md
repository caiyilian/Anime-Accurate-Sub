### 关键特性

| 特性 | 评价 |
|------|------|
| **OP/ED 检测** | 85-95s 连续音乐检测，自动丢弃整段。理论上对于 24min 动漫很有用，但本测试 30s 片段无 OP/ED |
| **四层幻觉防御** | SenseVoice 标签 → OP/ED 过滤 → Whisper no_speech_prob / compression_ratio → 呼吸语气词过滤。本测试中 0 句被拦截（片段无 BGM hallucinations） |
| **显存驻留三引擎** | fsmn-vad + SenseVoice + Stable-Whisper 常驻显存，无需每集重载 |
| **模型下载** | ModelScope 直连（国内友好），仅 SenseVoice-Small ~936MB |
| **Whisper large-v3** | ~3.1GB，从 VideoLingo 缓存复用，无需重新下载 |
| **ASR 质量** | 基本准确的日语识别，但 Segment #1 显示合并了双片段 "りつ!"+"クラブケース!"，Seg #9 截断为 "リッ" |
| **翻译** | 需要 DeepSeek API Key（本次未测）。Prompt 设计了 5 条纠错法则（同音反推、双关语保留、中二病还原、幻觉滤除、拟声词意译） |

### 可复用模块

1. **AnimeTranslator 的 OP/ED 检测器** — `_detect_op_ed_zone()`: 在视频前/后 5min 内检测 85-95s 连续音乐簇，识别并丢弃整段
2. **AnimeTranslator 的 SenseVoice 音频事件分类** — BGM/Speech/MUSIC 标签，替代传统人声分离
3. **AnimeTranslator 的 In-memory tensor slicing** — 波形加载到显存一次，后续片段通过 tensor slice 提取（0.3s padding），零磁盘 IO
4. **AnimeTranslator 的幻觉过滤链** — 四层拦截思路可复用
5. **JAVTrans 的 5 模型边界检测架构** — SpeechBoundary-JA 的职责分离设计（scorer→refiner→split→cut→cueqc）是评估中最先进的动漫边界方案，但依赖 Mamba2 CUDA 内核

### 不可直接复用的

- **JAVTrans SpeechBoundary-JA** — 5 个模型与 Mamba2/CUDA 深度绑定，无法独立提取
- **JAVTrans Pre-ASR CueQC** — 同样依赖 Mamba2 和专属 checkpoint 格式
- **JAVTrans Qwen3-ASR** — 模型已下载（3.8GB），但需要 Python 3.13+ 环境和完整 CUDA 编译链

### 测试过程

1. **torchcodec 问题**: 需要 FFmpeg 共享 DLLs（已下载 8.1.2 版），但 `torchcodec` 0.14.0 与 PyTorch 2.6.0 不兼容，`libtorchcodec_core8.dll` 加载时报 `OSError: [WinError 127]`（找不到指定程序）。已创建 stub 绕过。

2. **Mamba2 编译问题**: `mamba-ssm` 和 `causal-conv1d` 需要从源码编译 CUDA 内核，`--no-build-isolation` 模式下仍需 `wheel` 等依赖

3. **管道进展**: 绕过 torchcodec 后，管道成功启动到 "语音岛检测 2s" 阶段，说明音频提取、配置加载等基础流程正常

### 关键架构（来自 README + HISTORY.md）

```
SpeechIslandScorer v8 (speech-only Mamba2)
  → speech hysteresis islands
  → Outer Edge Refiner v1 (只修整 island start/end)
  → Semantic Split Verifier v1 (cut/continue/unsure 三分类)
  → Cut Edge Refiner v1 (共享绝对时间戳)
  → Pre-ASR CueQC v11 (ASR 前 keep/drop 路由)
  → Qwen3-ASR (Anime/Galgame 微调)
  → Boundary chunk subtitle timing
  → Subtitle Layout v2 (acoustic/display 双时间轴)
  → LLM 翻译 / SRT output
```

### 关键指标（来自文档）

| 模型阈值 | Precision | Recall |
|----------|-----------|--------|
| SpeechIslandScorer (0.6B, threshold 0.15) | 79.79% | 98.25% |
| Semantic Split (p_cut>=0.75) | 94.63% | 56.59% |
| Pre-ASR CueQC (threshold 0.95) | 98.35% | 86.23% |

### 核心特点

1. **SpeechBoundary-JA** — 不是传统 VAD，而是为字幕切分设计的 5 模型前置链，逐帧 speech prob → 语义切分 → 边界精修
2. **Pre-ASR CueQC** — ASR 前的智能过滤，基于 PTM 表征 + Mamba 时序建模，p_drop>=0.95 才丢弃，准确率 84.21%
3. **与 Qwen3-ASR 紧绑定** — Frozen PTM feature + 5 model checkpoint 与 ASR repo 一一对应，0.6B/1.7B 独立训练
4. **Subtitle Layout v2** — acoustic/display 双时间轴，20-frame 最小显示时间，7s 最大显示 soft guard

## 4. 结论

### 可直接复用的
- **AnimeTranslator 的 OP/ED 检测逻辑** — 简单有效，85-95s 连续音乐检测，可以独立提取
- **AnimeTranslator 的四层幻觉防御思路** — SenseVoice 标签 + Whisper 质量指标 + 规则过滤的组合策略
- **SenseVoice 音频事件分类** — BGM/Speech/MUSIC 标签，替代 Demucs 等重型人声分离

### 需要额外环境配置才能运行的

- **JAVTrans SpeechBoundary-JA** — 最先进的动漫边界检测系统，但需要 Python 3.13+ + FFmpeg Shared + Mamba2 CUDA 编译环境
- **JAVTrans Pre-ASR CueQC** — 模型级 ASR 前过滤，依赖完整的 JAVTrans 运行环境
- **JAVTrans Qwen3-ASR** — 动漫微调 ASR，模型已下载（1.7B 3.8GB / 0.6B 1.5GB），但运行需要完整环境

### 下一步建议
1. 优先提取 AnimeTranslator 的 OP/ED 检测模块加入候选 pipeline
2. JAVTrans 的边界系统需等 HF 代理问题解决后再评估
3. S2.2 可以继续评估 SubForge / N46Whisper / SubFlow / LinguaGacha
