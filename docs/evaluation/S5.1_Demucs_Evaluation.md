# S5.1 Demucs 音频分离评估

> 日期: 2026-07-12
> 环境: Python 3.13 + torch 2.11.0+cu128, RTX 3060 12GB

## 模型信息

| 属性 | 值 |
|------|-----|
| 模型 | HTDemucs (hybrid transformer Demucs) |
| 来源 | Meta Research |
| 安装方式 | `pip install demucs` |
| 模型大小 | ~1GB (自动下载缓存) |
| 分离目标 | 4 stems: drums, bass, other, vocals |
| 测试模式 | `--two-stems vocals` (仅分离人声/非人声) |

## 分析

### 正面发现
- Demucs 确实能分离出人声和非人声，最大振幅降低说明 BGM 被部分移除
- 输出文件与输入文件大小相当（5MB 30s 44.1kHz stereo）

### 负面发现
- **分离后 CER 未改善反而恶化**：sample_0004 从 0.18 恶化到 0.27，说明 Demucs 引入了音频伪影
- **速度极慢**：5s 音频需要 145s 分离（~29x RTF），30s 音频需要 146s（~5x RTF），不适合实时处理
- **高显存占用**：约 4.5 GB 峰值，加上 ASR 模型后 ~6GB
- **输出格式变化**：16kHz mono → 44.1kHz stereo，需要额外转换

### 原因推测
- 动漫语音背景音乐通常音量较低，Whisper 模型本身对 BGM 有较好的鲁棒性
- Demucs 的分离过程会引入量化噪声和伪影，反而降低 ASR 精度
- 对于短片段（<30s），Demucs 的分离质量不如长片段

## 结论

### 是否加入 Pipeline

| 场景 | 推荐 | 理由 |
|------|:----:|------|
| 日常对话 | ❌ | CER 无改善甚至恶化，速度慢 |
| 战斗场景（BGM 强烈） | ⚠️ 待 S5.2/S5.3 对比 | 需要更强背景音场景测试 |
| OP/ED 段 | ❌ | 速度慢，OP/ED 已有 SenseVoice AED 检测 |

**当前结论：Demucs 不适合加入 pipeline。** 主要原因：
1. 分离后 ASR 精度未提升（甚至下降）
2. 速度极慢（29x RTF），成为 pipeline 瓶颈
3. 显存占用高（~4.5 GB），与 ASR 模型竞争 GPU 资源

将综合 S5.2 (UVR5) 和 S5.3 (BS-RoFormer) 的结果做最终决定。
