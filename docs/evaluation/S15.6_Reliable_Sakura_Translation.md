# S15.6 Sakura 批量翻译可靠性修复

## 问题

主流程原来逐条调用 Ollama，既没有利用上下文，也没有校验返回行数和内容。远端模型
超时、少行、合并行或发生重复退化时，错误结果会直接写进字幕；S9 已实现的术语表与
翻译记忆也没有接入主 CLI。

## 修复

- 使用 SakuraLLM 官方 system/user prompt 和多行输入格式。
- Sakura 默认每批 16 行；GalTransl v2.6 按模型卡建议每批 10 行，并使用各自的
  temperature、top-p、repeat penalty 参数。
- Ollama 请求固定 `num_ctx=4096`，支持 `host:port` 和完整 URL，避免本机 Q6_K
  模型因 131072 默认上下文耗尽显存。
- 请求增加 300 秒超时、指数退避和 4 次重试。
- 严格校验返回行数、prompt 泄漏、异常长度、重复字符、未翻译日文及纯标点退化；
  批量结果异常时递归拆分，不猜测时间轴对应关系。
- 纯非语言提示（例如 `――ッ!?`）允许转换为中文全角标点，正常对白仍禁止纯标点
  结果。
- 每批只发送当前源文实际命中的术语，递归拆分后再次过滤，避免大词表诱发退化。
- 主流程接入共享术语表、JSONL 翻译记忆和原子写入的批次进度文件；每批完成即可
  恢复，不必整集重译。
- CLI 新增 `--glossary`、`--translation-memory` 和
  `--translation-batch-size`。

## 真机验证

测试日期：2026-07-15。输入均从 UTF-8 文件或环境变量读取，避免 Windows
PowerShell 原生管道代码页破坏日文假名。

| 场景 | 结果 | 耗时 |
|---|---:|---:|
| 远端 Sakura-14B，既有 10 行日文基准 | 10/10 行正确 | 13.70 秒 |
| 远端 GalTransl-7B v2.6，3 行《轻音少女》对白 | 3/3 行正确 | 0.98 秒 |
| 本机 Sakura-7B Q6_K，既有 10 行日文基准 | 10/10 行正确 | 8.34 秒 |
| 第 1 集真实 ASR，远端 Sakura-14B + 术语表 | 16/16 行正确 | 4.89 秒 |

第 1 集真实片段中：

- `お姉ちゃん、` → `姐姐，`
- `そろそろ起きないと。` → `差不多该起床了。`
- `――ッ!?` → `——！？`
- `ドキドキが止まんない` → `心跳不已`

本机 Sakura 的模型层实际仍在 `E:\AI\models`。使用独立端口即可恢复，不必重新
下载，也不会影响原来的 Ollama 服务：

```powershell
$env:OLLAMA_MODELS = 'E:\AI\models'
$env:OLLAMA_HOST = '127.0.0.1:11435'
ollama serve
```

配置中的 Sakura `host` 可设为 `127.0.0.1:11435`。

## 结论

远端 Sakura-14B 可继续作为整季主力，本机 Sakura-7B 已恢复为可用兜底，远端
GalTransl-7B 也已验证可用。真实片段暴露的剩余明显问题位于 OP 歌词 ASR，而不是
翻译模型：错误日文会被模型流畅地翻译成错误中文，下一阶段需要单独处理 OP/ED。

自动化回归：19 项全部通过。
