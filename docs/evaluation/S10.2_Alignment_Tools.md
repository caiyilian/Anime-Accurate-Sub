# S10.2 字幕对齐工具评估：ffsubsync + subcap + SubtitleEdit

> 日期：2026-07-13
> 目标：评估字幕对齐工具，判断是否值得集成到 pipeline 中

---

## 评估方案

| 工具 | 类型 | 用途 |
|:----|:-----|:------|
| **ffsubsync** | Python 库 | 基于音频指纹的字幕时间轴同步 |
| **subcap** | Rust CLI | 强制对齐 + 样式化 ASS 生成 |
| **SubtitleEdit** | 桌面 GUI | 全功能字幕编辑器（含 CLI） |

---

## 评估结果

### ffsubsync

**安装**: `pip install ffsubsync` ✅ 成功（0.5.0）

**测试方法**：
1. 使用 K-On! EP01 视频 + 5 段章节标记字幕（Prologue/Opening/Episode/Ending/Epilogue）
2. 手动将字幕偏移 +5 秒
3. 运行 ffsubsync 尝试修复偏移

**测试结果**：

| 指标 | 值 |
|:----|:----:|
| 处理时间 | 5.3s（25min 视频） |
| 检测偏移 | 57.34s（期望 5s）❌ |
| 对齐质量评分 | -9951.76（极低） |
| 输出偏移误差 | 90.16s（远未修复） |

**分析**：
- ffsubsync 需要**有实际对话内容的字幕文件**才能准确对齐
- 仅使用章节标记（Prologue/Opening 等）不足以提取有效语音特征
- 如果使用包含完整对话的字幕（如已有字幕组的 SRT），效果会好得多
- 在我们的场景中（从零生成字幕，没有参考字幕），ffsubsync 的用途有限

**结论**：❌ **不集成到 pipeline 中**。我们是从零生成字幕，没有已有字幕作为参考，ffsubsync 无法发挥作用。

### subcap

**状态**：Rust CLI 工具，需要 Cargo 编译。

| 检查项 | 结果 |
|:-------|:------|
| 预编译二进制 | ❌ 未找到 |
| Cargo 可用 | ✅ 可编译 |
| 编译复杂度 | 中（Rust 依赖） |
| 维护成本 | 高（需跟踪 Rust 更新） |

**分析**：
- subcap 提供强制对齐和 ASS 样式生成功能
- 需要编译 Rust 工具链，增加部署复杂度
- 其核心功能（ASS 生成）已由 pysubs2 覆盖（S10.1）

**结论**：❌ **不采用**。核心功能已被 pysubs2 覆盖，Rust 编译增加部署复杂度。

### SubtitleEdit

**状态**：未安装。

| 检查项 | 结果 |
|:-------|:------|
| 安装状态 | ❌ 未安装 |
| CLI 支持 | 有（需安装后使用） |
| 适用场景 | 人工校对出口 |

**分析**：
- SubtitleEdit 是最成熟的字幕编辑器之一
- 支持 CLI 批量处理、格式转换、时间轴调整
- 适合作为**人工校对出口**：用户可以用 SubtitleEdit 打开生成的 SRT 进行微调
- 但不需要集成到自动 pipeline 中

**结论**：⚠️ **不集成到 pipeline，但推荐用户安装用于人工校对**。

## 最终结论

### 对比总结

| 工具 | 集成到 pipeline | 用于人工校对 |
|:----|:--------------:|:-----------:|
| ffsubsync | ❌ 无参考字幕时无法对齐 | ❌ |
| subcap | ❌ 功能已被 pysubs2 覆盖 | ❌ |
| SubtitleEdit | ❌ 不需要 | ✅ **推荐** |

### 字幕生成方案（已确定）

```
ASR 翻译文本
  → pysubs2 生成 SRT/ASS（S10.1）← 已实现
  → 时间轴优化（重叠修复/CPS/换行）← 已实现
  → 人工校对（SubtitleEdit，可选）← 推荐但不强制
```
