# S15.8 主流程质量报告修复

## 问题

`anime_sub.py` 的质量阶段原来固定调用：

```python
run_quality_check([], [], report_path)
```

因此无论字幕好坏，`quality_report.json` 都显示 `total_segments: 0`。旧的第 1 集
报告正是 0 段，无法发现 30 秒超长字幕、重复字符、乱码或术语错误。

此外，checkpoint 和 `test_all.py` 仍断言流水线只有 5 个阶段，但正式常量已经包含
`embed_subtitle`，实际是 6 个阶段；文档曾报告 17/17，而当前代码会在阶段数断言处
失败。

## 修复

- 质量阶段读取真实 `translated.json`，转换为 `SubSegment` 后执行规则检查。
- 保留 `asr_confidence`，低于 0.45 的片段加入人工复核队列。
- 报告新增 `review_queue`，每个问题同时携带：
  - 时间轴；
  - 日文 ASR；
  - 中文译文；
  - 说话人；
  - ASR 置信度；
  - 规则、级别和原因。
- 主流程把质量统计写入返回结果，并把 glossary 传给术语一致性规则。
- CLI 未指定 `--output` 时自动在输入文件旁生成 `.quality.json`。
- 未开启 `--quality-check` 时 checkpoint 使用 5 个活动阶段；开启时使用完整 6
  阶段，避免摘要长期显示一个无意执行的 pending 阶段。
- 修正 checkpoint 自测和 `test_all.py` 的 6 阶段断言。
