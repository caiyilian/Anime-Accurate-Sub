# S11.3 GEMBA-MQM 翻译质量门禁评估

> 初版日期：2026-07-13
>
> 生产化复核：2026-07-19
>
> 目标：让 MQM 评分成为可接入、可断点、可审计且不会因单模型误判而自动改坏字幕的质量门禁。

## 复核结论

旧 `scripts/gemba_mqm.py` 是未接入主流程的演示脚本，存在四个核心问题：

- 四个维度分别调用同一模型，模型或解析失败时直接给默认 50 分，无法区分“质量差”和“评估失败”。
- 用正则从自然语言中抓第一个“评分”，不验证字段、错误证据或置信度。
- 故意增译样本只得到 65.2 分，默认阈值 60 没有触发重译，但旧报告仍把“低分段落可自动重译”标为完成。
- 新译文只要同一个裁判重评分数略高就标记 `improved`，没有最低最终质量、最小提升、独立复评或自动应用安全门禁。

该文件还有用户本地未提交的模型地址改动，本次没有覆盖或暂存它。生产实现放在新的 `scripts/mqm_quality_review.py`，主流程和总回归均使用新模块。

## 新流程

每条字幕按以下顺序执行：

1. `sensenova-6.7-flash-lite` 与 `deepseek-v4-flash` 并行独立给出四维 MQM 分数、最高严重度、逐条证据、修订建议和置信度。
2. 任一裁判以至少 0.75 置信度发现低于 80 分或 major/critical 错误，才调用 Flash Lite 总编。
3. 总编只有在置信度至少 0.85 且确有更准确完整译文时提出修订。
4. 修订候选再次交给 Flash Lite 与 DeepSeek Flash 独立复评。
5. 只有两位复评裁判都返回 `keep`、置信度达标、最低最终分至少 80、且相对初始最低分提升至少 5 分时，才允许自动应用。
6. 任一初评、总编或复评调用失败，保留原译并标为 `error`/`needs_review`。

结合 S11.2 多 Agent 后，Flash Lite 仍承担明显更多调用；DeepSeek 负责独立语义裁判，使用每账号 5 小时 500 次配额。六个账号继续共用线程安全 round-robin，密钥不进入配置、日志、报告或 Git。

## 严格 MQM 结构

四个维度及权重保持为：

| 维度 | 权重 | 重点 |
|:-----|:----:|:-----|
| accuracy | 35% | 错译、漏译、增译、主客体、否定、语气 |
| fluency | 25% | 中文语法、自然度、简洁度、字幕可读性 |
| terminology | 20% | 角色名、称呼、专名和前后一致性 |
| style | 20% | 人物语气、关系、情绪和动漫口语风格 |

模型必须返回完整 JSON：每维度包含 0-100 数值分、`none/minor/major/critical` 严重度和理由；错误列表必须包含日文证据、中文证据与说明；还需给 `keep/revise`、完整建议译文和 0-1 置信度。缺字段、额外字段、字符串分数、越界数值、提示词回显或“评分: 90”自然语言均会被拒绝并重试。

## 工程接入

- 可选 `mqm_quality_review` 阶段位于翻译/多 Agent 之后、字幕生成之前。
- 输入优先使用 `reviewed.json`，未启用多 Agent 时使用 `translated.json`；输出 `mqm_reviewed.json`。
- 字幕生成和规则质量检查使用 `mqm_reviewed.json`，不会继续读取旧译文。
- 完整报告写入 `mqm_quality_report.json`，断点写入 `mqm_quality_review.progress.jsonl`。
- 缓存键包含目标日中字幕、前后文、模型、阈值和 prompt 版本；相邻字幕或配置变化都会重新评分。
- 源文件和所有元数据保持不变，每段只追加精简的 `mqm_review` 审计摘要。
- CLI、整季批处理和 Web UI 均可启用；Web 可下载 MQM 输出与完整报告。

## 使用方式

主流程同时启用多 Agent 与 MQM：

```bash
python scripts/anime_sub.py video.mkv \
  --multi-agent-review \
  --review-config config/quality_review.sensenova.json \
  --mqm-quality-review \
  --mqm-config config/quality_mqm.sensenova.json
```

独立运行：

```bash
python scripts/mqm_quality_review.py \
  --input reviewed.json \
  --output mqm_reviewed.json \
  --report mqm_quality_report.json \
  --progress mqm_quality_review.progress.jsonl \
  --config config/quality_mqm.sensenova.json
```

只评估、不应用：

```bash
python scripts/mqm_quality_review.py \
  --input reviewed.json \
  --config config/quality_mqm.sensenova.json \
  --dry-run
```

## 生产级失败恢复

MQM 与多 Agent 使用相同的严格恢复语义：`error` 记录不会命中完成缓存，文件级审查最多自动执行 3 轮且只重试失败字幕，生产配置的模型调用重试数提高到 6。若仍有裁判或总编调用失败，诊断输出会落盘，但审查器抛出错误并阻止 MQM 检查点完成；后续使用原进度文件运行时继续复用成功结果、重试失败结果。

Flash Lite 裁判耗尽 6 次重试后，生产配置使用账号模型列表中独立的 `glm-5.2` 兜底；另一位裁判仍为 `deepseek-v4-flash`，禁止用 DeepSeek 替代 Flash 后形成两个同模型裁判。Flash 总编失败时也由 GLM 兜底。报告记录主模型、实际模型、是否兜底和主模型错误；兜底只影响失败恢复，不改变评分阈值或提示词，因此不会使已经成功的断点失效。
