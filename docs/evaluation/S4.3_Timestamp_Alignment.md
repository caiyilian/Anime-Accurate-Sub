# S4.3 时间戳对齐方案评估

> 日期: 2026-07-12
> 环境: Python 3.13 + torch 2.11.0+cu128, RTX 3060 12GB

## 背景

字幕时间戳对齐方案对比，选择是否启用 WhisperX 或 stable-ts 来改善时间轴精度。

## 候选方案

### 1. faster-whisper 原生时间戳（当前方案）

**状态**: ✅ 已在使用
**特点**:
- 默认提供 segment-level 时间戳
- 支持 `word_timestamps=True` 开启词级时间戳（无需额外依赖）
- 与我们的 Anime Whisper 模型完全兼容
- 零额外资源消耗

### 2. WhisperX (wav2vec2 对齐)

**状态**: ❌ 不兼容
**特点**:
- 提供 wav2vec2 词级对齐
- 但与 transformers 5.13.1 + Python 3.13 不兼容（`Pipeline` 类导入失败）
- 降级 transformers 会破坏 Qwen3-ASR 模型加载
- 日语 wav2vec2 模型可用性不确定

### 3. stable-ts (时间戳稳定化)

**状态**: ❌ 未测试
**特点**:
- 对 Whisper 时间戳做后处理平滑
- 主要解决 Whisper 时间戳抖动问题
- 需要额外依赖，且与当前 transformers 版本兼容性未知

### 4. JAVTrans SpeechBoundary-JA（未来方案）

**状态**: 🔜 将集成
**特点**:
- 5 模型语义边界检测链（SpeechIslandScorer → Outer Edge Refiner → Semantic Split → Cut Edge Refiner → Pre-ASR CueQC）
- 提供语义级切分，优于任何 VAD/时间戳对齐方案
- 时间戳来自 acoustic boundary，精度为 ms 级

## 结论

| 方案 | 推荐 | 理由 |
|------|:----:|------|
| faster-whisper 原生 | ✅ **采用** | 已在使用，word_timestamps 满足需求 |
| WhisperX | ❌ **不采用** | 依赖冲突，维护成本高 |
| stable-ts | ❌ **不采用** | 必要性低，额外依赖 |
| JAVTrans Boundary | 🔜 待集成 | Sprint 7 统一整合 |

**决策**: 不启用 WhisperX 或 stable-ts。faster-whisper 的 `word_timestamps=True` 参数已提供足够的时间戳精度。后续在 Sprint 7（整合阶段）将使用 JAVTrans 的 SpeechBoundary-JA 语义边界系统提供更精确的字幕时间轴。
