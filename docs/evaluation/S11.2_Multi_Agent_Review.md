# S11.2 多 Agent 字幕审查评估

> 初版日期：2026-07-13
>
> 生产化复核：2026-07-19
> 目标：用 5 个独立审查角色、总编仲裁和可审计的安全门禁，修正高置信度翻译问题。

## 复核结论

旧版原型虽然完成了脚本外壳，但没有接入 `anime_sub.py` 主流程，也没有真正可靠地完成自动修正。旧解析器会从模型复述的提示词中猜测 `[OK]` / `[FIX]`，留存评估 JSON 的实际结果是 20 个 `ok`、0 次有效总编调用；因此旧报告中的“3/4 需要修正”与“自动应用成功”不成立。

本次 v2 已完成生产化改造：

- 5 个角色并行审查：一致性、中文自然度、翻译准确性、ASR 合理性、动漫对白风格。
- 审查器和总编只接受完整 JSON 对象；不再从自然语言、提示词回显或关键词中猜结论。
- 至少 2 个高置信度 `fix` 票才调用总编；总编达到置信度阈值后才允许替换。
- 任意审查器失败都会阻止自动改写，结果转入人工复核，避免“部分 Agent 失联仍改字幕”。
- 支持 OpenAI-compatible API 和 Ollama；支持每个角色单独指定模型。
- 支持多行 API key 文件轮询、失败重试、JSONL 断点续传、上下文窗口和术语表。
- 审查阶段已接入 CLI 与 Web UI；启用后位于翻译和字幕生成之间，下游会消费 `reviewed.json`。
- 源翻译文件保持只读；完整投票、理由、置信度、总编结果和是否应用均写入审计报告。

## SenseNova 高质量配置

项目提供不含密钥的 `config/quality_review.sensenova.json`。按 SenseNova 官方模型文档（<https://platform.sensenova.cn/docs>）和账号限额，固定采用偏向高配额模型的 4:1 路由：

| 角色 | 模型 | 选择原因 |
|:-----|:-----|:---------|
| consistency / naturalness / asr_check / style | `sensenova-6.7-flash-lite` | 每账号 5 小时 1500 次，承担 4/5 审查调用 |
| accuracy | `deepseek-v4-flash` | 每账号 5 小时 500 次，专门承担语义忠实度复核 |
| editor | `sensenova-6.7-flash-lite` | 高配额模型负责最终仲裁 |

`config/sensenova_apikeys` 可按行保存多个账号。当前 6 个账号会以线程安全的 round-robin 方式轮询；每次重试继续取下一个账号。密钥值不会进入配置、日志、报告或 Git。

## 自动改写门禁

一条字幕只有同时满足以下条件才会被自动替换：

1. 所有 5 个审查器均成功返回有效 JSON；
2. 至少 2 个审查器给出 `fix`，且每票置信度不低于 `0.75`；
3. 总编明确返回 `replace`；
4. 总编置信度不低于 `0.85`；
5. 修正文本非空。

否则保留原译，并在报告中标为 `needs_review` 或 `error`。`--dry-run` 会生成完整报告，但绝不应用替换。

## 真实调用验证

### 故意错误样本

输入：

- 日文：`私は猫です。`
- 错误中文：`今天天气很好。`

使用上述 SenseNova 配置时，5 个角色全部判定需要修正，总编输出“我是猫。”，置信度 `1.0`，安全门禁允许应用。相同样本用 Sakura 翻译模型担任审查器时，5 个角色均错误放行且置信度为 `0`，说明 Sakura 适合翻译但不适合作为唯一质量裁判。

### 《轻音少女》真实样本

对第 9 集一条真实流水线结果进行审查耗时约 137 秒。准确性角色放行，自然度和风格角色建议修正，一个角色返回格式错误；总编虽给出高置信度替换，v2 安全门禁仍会因为审查错误而拒绝自动应用。

进一步与已下载的日文字幕对齐后发现，该行 ASR 日文本身与音频语义不符。这个案例说明多 Agent 可以降低译文错误，但无法稳定地从错误日文文本反推出原始音频。整季提质应先启用 S13.3 外挂日文字幕优先，再运行翻译和多 Agent 审查；中文翻译组字幕只用于生成完成后的盲评，不能进入生成上下文。

## 使用方式

主流程：

```bash
python scripts/anime_sub.py input.mkv --multi-agent-review \
  --review-config config/quality_review.sensenova.json
```

独立审查：

```bash
python scripts/review_agents.py \
  --input translated.json \
  --output reviewed.json \
  --report multi_agent_review.json \
  --config config/quality_review.sensenova.json
```

只审计、不改写：

```bash
python scripts/review_agents.py \
  --input translated.json \
  --output reviewed.json \
  --report multi_agent_review.json \
  --config config/quality_review.sensenova.json \
  --dry-run
```

## 生产级失败恢复

整季运行中，SenseNova 偶尔会返回空响应或暂时不可解析的结构。任一审查角色失败，或达到投票阈值后总编调用失败，都会把该字幕标记为 `error`；失败记录不会再被断点文件视为已完成。每次文件审查最多自动执行 3 轮，仅重试仍为 `error` 的字幕，已经成功的结果继续从 JSONL 断点恢复。生产配置同时把单次模型调用重试提高到 6 次，以配合 6 个账号轮询。

如果 3 轮后仍存在失败项，审查器会保留诊断报告并抛出错误，主流程不会把多 Agent 检查点标记为完成；使用同一个进度文件重跑即可继续失败项，禁止带错误静默进入下游。断点加载器也会识别旧版本曾写成 `needs_review`、但嵌套总编决策实际为 `error` 的历史记录，并自动使其失效重试。
