# Anime Accurate Sub - 项目需求文档

## 项目概述

输入一个视频文件，自动嵌入精准的中文字幕。主要用于没有中文字幕的日语动漫视频。

## 核心痛点

- 日语动漫缺乏中文字幕，手动找字幕很麻烦
- 浏览器自动字幕翻译工具（如 YouTube 自动翻译）错误率很高，翻译不准确
- 现有方案对动漫领域的专有名词、角色名、语气词等处理较差

## 核心需求

### 1. 语音识别 (ASR)
- 从视频中提取日语语音
- 对日语动漫语音有较高的识别准确率
- 支持说话人区分（角色分离）

### 2. 翻译 (Translation)
- **日语 → 中文** 的准确翻译
- 对动漫场景、口语化表达、角色语气有良好表现
- 保持角色名称翻译的一致性
- 支持专有名词（招式、地名、术语等）的准确翻译

### 3. 字幕嵌入 (Subtitle Embedding)
- 将翻译后的中文字幕嵌入视频文件
- 支持 ASS/SRT 等常见字幕格式
- 字幕样式美观（字体、大小、位置、描边等）
- 支持双语字幕（日语原文 + 中文翻译）可选
### 4. 本地运行 (Local Execution)

- **必须支持通过 Ollama 运行本地模型**，不需要依赖云端 API
- 也可选支持调用云端 API（如 OpenAI、Claude、DeepSeek 等）作为备选
- 敏感数据不上传外部服务

> **当前状态**: Ollama 模型下载因网络问题暂时搁置，先用 Sensenova API（商汤大装置，免费额度 1500 次/5 小时）作为临时翻译后端。API 兼容 OpenAI 格式，后续切回 Ollama 只需改 base_url。

## 技术栈方向

| 模块 | 候选方案 |
|------|---------|
| ASR 主力 | anime-whisper（litagin） |
| ASR 快速备选 | SenseVoice Small |
| ASR 复核 | Qwen3-ASR-1.7B-JA |

| 翻译主力 | SakuraLLM（Sakura-7B/14B）via Ollama |

| 持久化 | JSONL + 原子写入（复杂后考虑 SQLite） |

## 工作流程

```
输入视频文件
    ↓
┌─ 可选前置：人声/BGM 分离（Demucs/UVR5） ─┐
│  （战斗/音乐密集场景推荐开启）              │
└──────────────────────────────────────────┘
    ↓
提取音频轨道 → 断点续传 (Checkpoint)
    ↓
ASR 识别（Anime Whisper 主力，可疑段 Qwen3-ASR 复核）
    ↓
日语原文 + 词级时间戳 → 断点续传
    ↓
（可选）说话人分离
    ↓
上下文窗口翻译 ← 带术语表 ← 查翻译记忆
  （本地 <30G 显存：Python 拼接上下文窗口）
  （服务器 / API：让模型自由调用工具阅读上下文）
    ↓
中文翻译 → 断点续传 → 更新翻译记忆库
    ↓
字幕生成（SRT/ASS）+ 时间轴优化
    ↓
（阶段 2+）多 Agent 脚本审查 → 可疑行检测 → 修正
    ↓
嵌入视频 → 输出带字幕的视频
```

### 上下文窗口翻译策略

日语大量省略主语，逐句翻译必然导致人称混乱，必须带上下文翻译。

**本地模式（显存 <30GB）**：
- Python 在调用翻译前，将当前待翻行 + 前后 3-5 句原文 + 已有译文拼接到 prompt
- Ollama 模型不调用工具，只做纯翻译

**服务器 / API 模式（显存充足）**：
- 大模型自行调用工具读取上下文
- 可自由决定需要多少上下文
- 适配 OpenAI / Claude / Ollama 远程等各类后端

## 功能路线图

### 阶段 0 — 基础管道（MVP）

- [ ] **基础流水线** — 视频→音频提取→ASR→翻译→字幕生成→嵌入视频，全流程跑通
- [ ] **上下文窗口翻译** — 翻译时带前后 3-5 句上下文，避免逐句翻译导致人称混乱
- [ ] **断点续传（Checkpoint/Resume）** — 每个阶段写入 JSONL checkpoint + 原子写入，中断后自动跳过已完成阶段
- [ ] **术语表系统（Glossary）** — 用户自定义角色名/招式名/地名翻译映射，SakuraLLM GPT 字典格式（阶段 0 末期加入）
- [ ] **字幕时间轴优化** — 基础优化：重叠修复、最短/最长时长控制、阅读速度（CPS）控制

### 阶段 1 — 管道完善

- [ ] **人声/BGM 分离预处理** — 集成 Demucs / UVR5 / BS-RoFormer，作为 ASR 前置可选项，战斗/音乐密集场景分离纯净人声后 ASR 错误率可降 15%-30%
- [ ] **OP/ED 自动检测与跳过** — 自动识别片头片尾音乐段，节省 ASR 资源，避免翻译歌词
- [ ] **双语字幕模式** — 日语原文 + 中文翻译同时显示，上日下中或左日右中布局
- [ ] **翻译记忆库（Translation Memory）** — JSONL 双层缓存（精确匹配 + 跨会话持久化），相同台词自动复用
- [ ] **说话人分离与角色标注** — Kotoba-Whisper v2.2 内置起步，进阶考虑 DiariZen；注意动漫场景准确率有限，标注角色名前需人工确认
- [ ] **翻译 Adapter 模式（架构设计）** — 翻译接口做成适配器：SakuraTranslator（默认）→ QwenTranslator（许可证友好 fallback）→ GalTranslTranslator（风格备选）→ ExternalAPITranslator（API 备选）

### 阶段 2 — 质量完善

- [x] **多 Agent 脚本审查** — 5 个角色并行审查一致性/自然度/准确性/ASR/风格，总编仅应用高置信度共识；支持 SenseNova 多账号轮询、完整审计和断点续传
- [ ] **专有名词自动发现** — 从全片台词中聚类高频专有名词（角色名/招式名/地名），生成术语表草稿供用户确认
- [ ] **可疑字幕行检测** — 自动标记 ASR 低置信度、BGM 干扰段、术语不一致、CPS 过高等可疑行，用户只需校对 30-50 行高风险片段
- [ ] **A/B 模型评测小工具** — 基于公开的字幕文件 + 对应动漫片段，自动对比不同 ASR/翻译模型的 CER、术语命中率、空翻译率
- [x] **外挂字幕优先模式** — 支持单文件、整季目录和内嵌日文文本轨；校验语言/集数/源指纹后跳过 ASR，源变化自动重建下游，缺失时可安全回退 ASR
- [ ] **批量处理** — 一次性提交多集动漫，自动排队处理
- [ ] **多种字幕样式模板** — 提供多套 ASS 预设样式（字体、大小、颜色、描边、位置等）

### 阶段 3 — 高级功能

- [ ] **整季级一致性记忆** — 跨集保存角色名、角色关系、口癖、称呼方式，保证全季翻译一致性（锦上添花，优先级最低）
- [ ] **翻译 Adapter 模式（完整实现）** — 多后端自由切换，配置文件即可切换翻译引擎
- [x] **说话人分离 — 角色颜色前缀** — 不同角色使用不同颜色标签在字幕中显示；角色身份映射可配置，自动识别结果仍需人工确认
- [x] **Web UI 界面** — 图形化操作界面，上传视频 → 配置参数 → 下载结果
- [x] **人工校对模式（Proofreading）** — 交互式界面让用户校对和修正翻译结果，支持导出/导入校对稿
- [ ] **翻译质量评估（TQE）** — GEMBA-MQM + Ollama 自动评分，标记低置信度段落
- [x] **插件系统** — 允许社区开发翻译后端、ASR 后端、字幕样式等插件
- [x] **视频预览** — 快速生成短片段字幕预览，所见即所得
- [ ] **支持更多语言对** — 如英语→中文、日语→英语等

## 非功能性需求

- 支持 GPU 加速（CUDA）
- 良好的断点续传能力（避免长视频处理中途失败全部重来）
- 清晰的日志输出，方便排查问题
- 模块化设计，各组件可独立替换（ASR / 翻译 / 字幕引擎解耦）
- 自动检测硬件配置，推荐最优参数（模型大小、量化级别等）
